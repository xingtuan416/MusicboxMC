## 一、界面与文案

### 修复 1：BPM 显示成小数

**现状**：显示只有一处，`src/renderer/app.js:260` 直接拼 `result.song.baseBpm`；这个值一路来自 `src/core/midi/parse.ts:74`，再往上是库的 `60000000 / microsecondsPerBeat`（`node_modules/@tonejs/midi/src/Header.ts:101`），全程浮点，所以会出现 `70.0003150014175`。

**改法**：显示层四舍五入到整数，数据不动（检查页、开发者面板仍可看精确值）。没有 tempo 事件时本来就是 120，不受影响。

**边界**：真实 70.5 会显示 71；122.0000691 显示 122。

**验收**：新增渲染层断言（`scripts/verify-ui.cjs` 里对 `#valBpm` 断言整数正则）。

### 修复 2：第二步文案 + MIDI 是什么

**改法**：

**验收**：`verify:ui` 里点开问号、断言气泡可见且含「MIDI」；文案断言用新句子。

### 修复 4：读不了的错误要藏起来

**现状**：`src/renderer/app.js:226-234` 把 `error.message` 原样写进详情；这条 message 由主进程 `src/main/index.ts:156` 拼成「解析失败：…」，非 CoreError 时 `src/main/messages.ts:96` 直接透传库的英文（如 `Bad MIDI file.  Expected 'MHdr', got:`），外层还带 Electron 的 `Error invoking remote method 'song:analyze':` 前缀。

**改法**：行内只显示「这个文件读不了」+ 一句推测（「可能不是 MIDI 文件，或者文件损坏了」）；技术原文折叠进「技术细节」默认收起，保留复制按钮。**没有技术原文我就没法定位用户报的问题**，所以我建议留着、但默认不展开。

### 修复 5：单音轨不显示主音轨卡

### 修复 8：命令播放时隐藏多余选项

**现状**：命令播放时，`app.js:632-698` 只把开关 `disabled = true` 并加一行小字解释，**一张卡都不隐藏**；而禁用样式只有 `opacity: .45`（`index.html:1157-1160`），`aria-checked='true'` 的胶囊底色照旧是亮色——就是你说的「看着是开的，但点不动」。

**改法**：命令播放时隐藏 按主轨排序 / 稀疏音轨借道 / 相邻轨道取电 / 投影注释 / 合并方式；后端忽略。真的要保留的禁用控件，把胶囊改成明确的关闭态（旋钮回左、底色去 accent）。

### 修复 9：资源包卡按需显示 + 永久隐藏

**现状**：卡片 `index.html:2663-2689` 恒显示、没有 id、JS 只换文案（`app.js:610-618`）；生成完成弹窗在 `src/renderer/resourcepack.js:119-123`，靠 `localStorage` 的 `musicboxmc.resourcePackPrompted`（`:19`）**全局只弹一次**，弹窗里只有「以后再说」和「保存资源包」。

**改法**：

- 不需要资源包时整张卡不渲染（不是只换文案）；
- 需要时保留卡片，并在生成完成后弹提示；
- 弹窗加勾选框「以后不再提示」：勾了就永久隐藏（存 localStorage），不勾就**每次生成都提示**（去掉现在的一次性逻辑）。

### 修复 10：记住上次保存位置

**现状**：`src/main/index.ts:196-203` 的选择目录对话框没有 `defaultPath`；授权表 `src/main/outputPaths.ts:14-15` 是进程内 Map，重启即失效，所以现在每次都要从头选。

**改法**：主进程把上次选的目录写进 `userData` 下的小 JSON；对话框带上 `defaultPath`；启动时把记住的目录重新登记为「上次目录」这一条授权，界面第 5 步直接显示它，用户想换再点按钮。

**安全边界**：授权仍然只针对用户自己选过的那一个目录，渲染层拿不到任意路径的写权限。

## 二、优化 1：中继器要均匀

**为什么会前稀后密**：`src/core/layout/track.ts:316-324` 分配补齐格时，先把最后一槽塞到 `lastSlotCap`（≤13），剩下的**从前往后每槽一次吃满 13 格**。于是前面的中继器间距最大能到 14 格，后面拿不到补齐，就是一长串裸中继器（间距 1 格）。`track.ts:298-305` 的注释写明这是为了分支强度预算从「均匀」改成「前载」的。

**一个必须先说清的事实**：粉和中继器都占 1 格，**总长度由时间轴决定，改分布不会让轨道变短**。《鸟之诗》3,615 红石刻就是 3,600 多格，这一条没法靠排布解决。你能看到「跑到渲染距离上限」，是曲子本身长；能改的是**密度均匀**与**玩家身边那一段的观感**。

**改法**：

- 最后一槽仍然保留 `lastSlotCap`（分支强度靠它）；
- 其余补齐在剩下的槽里**均分**（每槽 ≤ 13 格，余数从中间往两边摊）；
- 结果：一段车头里中继器间距基本一致，不再出现「14 格 … 1 格」的跳变。

**玩家 X**：现在布局只知道玩家站哪一行（Z），不知道 X。可以顺手算出**音符盒的平均 X**（遍历 `tracks[].placements` 里的 note_block 取均值取整），写进结果与注释牌（「站这里 · X≈1345」），这样玩家知道该站在哪一段。要不要这么做见 Q10。

**已实现（第十六轮）**：新增 `distributePad(pad, caps)`（`src/core/layout/track.ts`），轮询式给每个槽 +1，最后一槽仍是 `lastSlotCap`，补齐总格数不变。夹具 `happy-birthday-16.mid`（dMax 8）实测：改前主行最大连续裸中继器 32–38 个、最长粉串 14 格；改后 3–4 个、粉串 ≤4 格。`test/relaySpacing.test.ts` 5 条把它钉住（用 `git show HEAD:src/core/layout/track.ts` 换回旧实现会失败）。玩家 X 用音符盒平均 X 写进 `AnnotationOptions.playerX`，界面显示「站 (x, y, z)」。

## 三、优化 2：预览要跟手

**根因（已定位，不是显卡也不是数据量）**：

1. `src/renderer/preview.js:193` 把 `clampView` 的结果**写回** `state.previewView`，而 `src/renderer/previewGeometry.js:86-93` 把偏移四舍五入成整数 —— 每帧的亚格位移被抹掉，下一帧又从整数基点重算，**永远攒不起来**。默认 28px/格时，位移不到 14px 画面就不动，超过就整格跳一下，看起来就是「横向不跟手」。
2. 两个轴各自独立取整，谁先过 14px 谁先跳，于是斜向拖动看起来像锁了一个轴。
3. 每帧从零全量重画（五趟循环 + 中继器的 `shadowBlur`），`preview.js:174-183` 每帧还读两次 `getComputedStyle`。

**改法**（就是你说的「做成一张图片」）：

- 格子层画进离屏瓦片（512px，LRU 缓存），拖动时只做带小数偏移的 `drawImage`；
- 标尺、图例、焦点框这些「镀铬」每帧原位重画，避免跟着漂；
- 停止把取整结果写回状态，让小数偏移成为权威值；
- 拖动 / 滚轮 / 滚动条统一进一个 `requestAnimationFrame` 调度器；缩放或切图层时失效缓存。

**验收**：`previewGeometry` 加单测（连续 3 次 5px 拖动后偏移累计 15px）；`verify:ui` 加手势脚本（斜向拖动 200px，断言视口偏移与指针位移一致）。

### 已实现（第十六轮）

- **瓦片**：`TILE_SIZE = 384`、`tileCells(cell)`、`cellRangeForView()`、`tilesForView()` 都在 `src/renderer/previewGeometry.js`；瓦片锚定在「格数 = span 的整数倍」上，与视口无关，所以平移只建滚进来的那几张。缓存是 `Map` 的插入序 LRU，上限 `TILE_LIMIT = 16`（一屏约 8 张，留一屏的滚动余量）。
- **合成**：`src/renderer/preview.js` 先把每张瓦片按 `deviceSize = round(span × cell × dpr)` 画进自己的 canvas，再用 `ctx.drawImage(tile, baseX + tx × deviceSize, baseY + tz × deviceSize)` 按设备像素对齐拼回去；格坐标 `(baseX + gx × step) / dpr` 保留小数，这就是「跟手」的来源。
- **镀铬**：标尺、左槽、边框、焦点框每帧原位重画；图例只在乐曲变化时重建，读数用 `setText` 比对后写，画布 padding 用 `WeakMap` 缓存，不再每帧 `getComputedStyle`。
- **阴影**：中继器与音符盒的 `shadowBlur` 换成 1px 硬边（`drawTileLip`）——它是整趟绘制里最贵的调用，而且在瓦片里会糊出边界。
- **调度**：拖动与滚轮统一成 `requestAnimationFrame` 聚合（`src/renderer/app.js` 的 `pending` / `wheelPending`），一次手势最多一帧。
- **观测**：`previewDiagnostics()` 返回 `{ tiles, builds, lastDrawMs, view }`，`scripts/verify-ui.cjs` 通过 `window.__preview` 读它判断缓存有没有被复用。
- **验收实测**：`test/previewGeometry.test.ts` 16 条（小数偏移、瓦片跨格数、覆盖视口、锚定网格、平移复用、不越界）；`npm run verify:ui` 里 7px 斜向拖动实测两轴各移动 0.25 格，连续 4 次 6px 平移 `builds` 不增长，900px 滚动才会建新瓦片。把 `clampView` 改回四舍五入，实测「7px 拖动移动 0.000 格」；把 `TILE_LIMIT` 改成 0，实测「短平移重建了瓦片（17 → 53）」。
