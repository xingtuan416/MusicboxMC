# MusicboxMC 功能逻辑说明（不含代码）

这份文档回答「每个功能到底是怎么实现的」，只讲逻辑，不贴代码。每一节末尾给出源码位置（`文件:行`），你可以让任何人逐条核对。常量的具体数值统一放在 `docs/constants.md`。

阅读顺序建议：第 0 节的术语 → 第 1 节流水线 → 之后按你关心的功能跳读。

## 0. 三个词，以及我之前为什么写错

- **音轨**（MIDI 音轨）：MIDI 文件里的一条 track。界面里的「轨 1」= 音轨号 + 1。它是**输入**。
- **轨道**（MC 轨道）：生成出来的那条红石主线——一条主行、它自己的和弦分支行、下面的支撑块与地板。它是**输出**。一个音轨通常对应一条轨道；合并或借道时，多个音轨共用一条轨道。
- **行 / 列**：行是 Z 方向（南北）的格，列是 X 方向（东西）的格。

我之前在文档里把 MC 轨道写成「车道」，这是我自己造的比喻：代码里布局的 `track` 和 MIDI 的 `track` 同名，我想区分「排布出来的那一条」，就借了交通的说法。MC 里没有「车道」，这个比喻对你（在 MC 里看投影的人）不成立，也让「轨道居中」「轨道宽度」这些话变得含混。从这份文档起统一：**音轨 = MIDI 输入，轨道 = MC 输出**。界面文案原本也有「赛道」（例如「相邻赛道取电」），第十一轮已按你的要求全部改成「轨道」；MIDI 那一侧继续叫「音轨」。

## 1. 整体流水线

`MIDI → SongModel → 乐器分配 → 智能分流 → 排布 → 切区域 → .litematic`，另有一条命令播放后端和一层界面。

1. **读 MIDI → SongModel**：每个音符变成 `{音高, 开始秒, 时值秒, 力度(0-1), 通道}`，时间已经换算成秒（源文件里是 tick + tempo 表）。通道 9（0 基）视为鼓。轨道名与 GM 音色号保留下来给乐器分配用。见 `src/core/midi/types.ts:1-13`、`src/core/midi/parse.ts:54-65`。
2. **分配乐器**：优先级固定为 GM 音色 → 通道 9 鼓 → 轨道名 → 竖琴兜底（项目硬性规则，见 `AGENTS.md`）。两种模式：`native` 每条音轨用自己的乐器；`extended` 把音符摊到 5 个「钢琴槽」上（需要配套资源包才像钢琴）。超范围的处理策略为 `warn / clamp / octave / drop`。
3. **智能分流**：把整首歌归类（纯竖琴 / 单乐器 / 多乐器，`src/main/smartSelection.ts:13-24`），再分别**实测**四种候选布局的听距半径：不合并、借道、同乐器合并、强制合并，按 30 / 48 两个阈值挑。规则见第 7 节。
4. **排布**：第 2–6 节。
5. **切区域**：默认一条轨道一个 region，坐标平移到该 region 自己的原点；注释牌是独立的一个 region。但如果某条轨道的包围盒里会包住**别的轨道**的方块（深和弦的轨道很高，借道走廊会从它中间穿过去），这条轨道就按 Z 行切成几条带（band），保证任何 region 的盒子里都只有自己的方块——否则同一个坐标会出现「一个 region 说空气、另一个说中继器」的自相矛盾（`src/core/layout/regions.ts:34-58`、`:162-175`）。
6. **写 .litematic**：gzip 压缩的 NBT，`dataVersion 3700`、litematic 版本 `6`（`src/core/litematic/build.ts:30-31`）。

命令播放后端（第 11 节）不铺红石，同样导出 `.litematic`。

## 2. 一条轨道长什么样

沿 +X 方向依次是：`[红石粉补齐] [前置中继器] [分支列] [末级中继器] [音符盒] [下一组] …`（`src/core/layout/track.ts:176-240`）。

- **组** = 同一个红石 tick 要响的所有音符。组里第一个音（内联音）在主行上，由末级中继器直接点亮；其余音沿 ±Z 展开成和弦分支行。
- **≤3 个音**：只给内联音符一个中继器，两侧相邻行的音符盒被「单跳」点亮——被中继器强充能的音符盒会把电传给相邻的方块，但只限一格。这样不花红石粉，小和弦只占 2 格（`src/core/layout/track.ts:355-373`、`src/core/layout/model.ts:187-215`）。
- **≥4 个音**：分支列必须竖着铺红石粉（一格传导不够）；同一列的红石粉是一个连通网络，所以整列同时通电；每行一个中继器、延迟都等于主行末级中继器的延迟，整组同一红石 tick 响（`src/core/layout/model.ts:187-227`）。
- **一列能放多少音**：`2×dMax+1`（默认 dMax 14 → 29 个：内联 1 个 + 两侧各 14 行，`src/core/layout/model.ts:54-57`、`:60-64`）。这个上限来自红石粉信号：第 d 行外侧只剩 15−d 点，分支中继器至少要 1 点输入，所以 d ≤ 14。超过上限不报错，而是拆出第二条轨道（`POLYPHONY_EXCEEDED` + `TRACK_SPLIT`，`src/core/layout/groups.ts:205-221`、`src/core/layout/index.ts:751-755`）。
- **时间靠什么流动**：中继器点亮音符盒 → 被点亮的音符盒给身后的红石粉供电 → 下一组的前置中继器从这块粉取电。所以主线能一路往下走（`src/core/layout/model.ts:31-35`）。这一步依赖「音符盒是导体」：音符盒是完整的不透明方块，原版的非导电例外名单（红石块、侦测器、活塞等）里没有它，所以被中继器强充能后就能给相邻红石粉供电——2026-11-18 用公开资料核对过，见 `docs/constants.md` 第十八节。
- 两条造型硬规则：同时响的音符行必须**相邻**（隔空行没用又浪费高度）；补齐只能用红石粉，**绝不能加中继器**（红石粉零延迟，中继器有延迟）。见 `AGENTS.md` 硬性规则 7、2。

## 3. 时间轴怎么算

- 输入是秒 → 先量化到游戏刻（20 游戏刻/秒，一刻 50ms）→ 再量化到红石 tick（1 红石 tick = 2 游戏刻 = 0.1 秒）。见 `src/core/tempo/tick.ts:2-6`、`src/core/layout/model.ts:39`。
- 组间隔：`gap = 本组红石 tick + 全曲 lead-in − 上一组红石 tick`；末级中继器 `r = min(4, gap)`；剩余 `rest = gap − r` 由前面串联的中继器承担，每 4 点延迟一个中继器，`restCells = ceil(rest/4)`（`src/core/layout/track.ts:272-275`、`docs/redstone-model.md:87-94`）。
- **全曲 lead-in（base）只能是 0 或 1**：中继器最小延迟是 1 红石 tick，落在 0 时刻的组最早也要 1 tick 后才响。若每条轨道各自推断，轨道之间的相对时间就错了，所以 `layout()` 一次算全曲并统一传下去（`src/core/layout/track.ts:78-88`、`263-269`；启动 lead-in 只报一次：`src/core/layout/track.ts` 的 `STARTUP_LEAD_IN`，发出点 `src/core/layout/index.ts:685`）。
- **误差**：红石后端要量化两次，最坏 ±75ms（1.5 游戏刻），不是界面早期声称的 ±25ms（`src/core/tempo/tick.ts:14-23`）。单个音符实际与计划差超过 1 游戏刻就报 `TIMING_ADJUSTED`（`src/core/layout/track.ts:408`）。
- **速度表**：按 `/tick rate` 换算，预设倍率 1.0 / 0.75 / 0.5 / 1.5 / 2.0，实际时长 = 原时长 ÷ 倍率（`src/core/tempo/speed.ts:16-25`；默认表在 `src/main/generate.ts:62`）。

## 4. 多条轨道为什么不会越走越散（空间对齐）

- 问题：每条轨道单独铺时，密处耗格多、稀处耗格少，长曲子里能差出几百格，听上去就不像一个演奏。
- 做法：全曲建一条「时间 → X」参考线，取所有轨道可达位置的**上包络**（`src/core/layout/model.ts:98-156`、`docs/redstone-model.md:105-124`）。
- 参考线从每条轨道**实际补齐后的位置**递推，不能只看自然位置——丢掉「之前补齐过」会让曾经补齐的轨道悄悄超前（项目硬性规则 8；递推实现 `src/core/layout/index.ts:659-670`）。
- 只在落后超过容差时才补：**同步点**（≥2 条独立轨道同时有音）容差 0，其它地方 12 格（`src/core/layout/track.ts:279-293`）。
- 补齐只用红石粉，单段 ≤13 格（信号强度 15 留 1 格余量）；补不够就报 `SPATIAL_DRIFT`，**绝不为了几何改时间**（`src/core/layout/track.ts:294-315`、`src/core/layout/model.ts:88-96`）。
- 宽和弦的最后一格槽位还要给分支列留电，所以那一段的补齐上限更小（`src/core/layout/track.ts:295-305`）。这是历史上「宽和弦外圈没电」的修复。

## 5. Z 方向怎么分层

- 每条轨道先算自己上下各需要几行放和弦：2 个音只向下 1 行，4 个音向上 1 行、向下 2 行——两侧不对称，所以逐轨算（`src/core/layout/model.ts:169-249`）。
- 轨道之间留**恰好一行**空白。历史版本按全曲最宽和弦预留，两条单行轨道之间也会隔 6 行以上，把下一条轨道推出听距。
- `trackPitch` 若显式给数字，则是最小中心距，且永远不会压出碰撞（`src/core/layout/index.ts:719-741`）。
- **玩家站的那一行是固定的**：主音轨的红石粉行放在 z = 0，玩家站这一行（`src/core/layout/index.ts:740`）。其余轨道按优先级依次放到「当前更浅的一侧」——谁离玩家近，谁就先占位，所以离玩家的 Z 距离与重要度一致（双侧游标 `aboveLimit` / `belowLimit`，`src/core/layout/index.ts:683-752`）。
- **按主轨排序 / 按文件顺序**：打开（默认）时按上面的优先级铺；关掉就按 MIDI 文件里的轨道顺序铺，但玩家仍然站主音轨那一行（`GenerateOptions.standTrackIndex`，`src/main/generate.ts:229-249`、`src/core/layout/index.ts:639-643`）。这两个开关只改左右次序，不改「站哪一行」。
- **听距是半径，不是宽度**：`hearingSpot()` 先定站行，再取所有音符盒里离这一行最远的 Z 距离（`src/core/layout/hearing.ts:25-44`），写进 `LayoutResult.playerZ` / `hearingRadius`。所以“投影总宽 82 格”不等于“听不到”——玩家站中间，两侧各 41 格，都在 48 格以内。
- X 方向的顺序没有变：所有轨道的音符都沿 X 递增，多轨之间靠共享 X 参考线对齐（第 4 节）。

## 6. 主音轨怎么认

- 只看 MIDI 力度。音符盒输出电平固定，力度传不进投影，所以“谁更响”只能从源演奏判断（`src/core/arrangement/prominence.ts:3-10`）。
- 排序规则就一条：平均力度（`meanVelocity`）降序；一样响时比音符数（多的在前），再一样就按文件里的轨道号（`src/core/arrangement/prominence.ts:101-108`）。2026-11-18 第十一轮之前还有「力度差 0.03 以内改用综合分」和「打击乐不参与」两条，按你「只考虑力度」的要求都删掉了。
- 依据只剩两种：`velocity`（自动算出来的）与 `manual`（你在第 3 步下拉里选的）（`src/main/smartSelection.ts:115-136`）。
- **主音轨永远存在**：智能开关、合并方式都不影响它，`generate()` 与 `measureLayout()` 都会算（`src/main/generate.ts` 的 `planLayout`）。
- 结果用在四处：玩家站它的红石粉那一行（z = 0）；其余轨道按它的排序决定由近到远；注释牌标「主音轨 / 站这里」；借道与取电把主音轨排除在「稀疏」之外。

## 7. 合并的四条路，为什么听距说了算

- **不合并（off）**：一个音轨一条轨道。最忠实，也最宽。
- **借道（share）**：稀疏音轨并到别的轨道上，轨道数减少、音符数不变（第 8 节）。
- **同乐器合并（same）**：同乐器的音轨并成一条轨道——钢琴扩展算一类、每种固定乐器各算一类、通道 9 的鼓永不合并（`src/core/layout/index.ts:112-116`）。合并后同时响的音会变成和弦，超过单列容量时拆成新轨道（`TRACK_SPLIT`）。
- **强制合并（force）**：全曲一条主线，紧凑拓扑。它不能拆轨（拆了就不是一条主线），所以容量更紧：`min(2×dMax+1, 27)`（默认 27，比普通布局的 29 少两行——紧凑列由入口/上一组经一格红石粉供电，根到达强度只有 14，每侧只能 13 行）。任何一组超过它，**整条主线**改用两行 staged 总线，多花高度和全曲统一的启动延迟（`src/core/layout/forced.ts:190-198`、`AGENTS.md` 规则 7）。
- **选择规则**（`src/main/smartSelection.ts:50-72`）：听距半径 < 30 格就什么都别动；否则把四种候选**实测**半径，能进 48 格的最窄者胜；并列时按 借道 → 同乐器合并 → 强制合并 的顺序优先（也是尝试顺序）；一个都进不了 48 就取最窄；若「不合并」本身就是最窄，就不动。
- 为什么必须实测：合并有时会让布局**更宽**（和弦行变多、超容拆轨），所以任何「合并一定更窄」的假设都是错的（`src/main/smartSelection.ts:36-43`）。
- **接受条件（第十一轮改）**：不管是借道还是合并后折一次，只有「轨道数变少 且 听距半径不比原来差」才采用——预算是 `max(原半径, 48)`（`src/main/generate.ts:563-564`、`:599-600`）。所以合并把和弦行铺深一点、Z 稍微变宽，只要最远音符仍在你听得到的地方，就值得做；以前的“Z 不许变宽”会把这种改善直接拒掉。
- **合并之后再折一次**：同乐器合并之后，还会在合并出来的轨道上再跑一次借道（`laneFoldPlan`）；这一步禁止新建「收集轨」，否则会把合并特意分开的乐器又混回去（`src/main/generate.ts:309-354`、`src/core/arrangement/laneSharing.ts:36-44`）。
- **强制合并时借道与取电不存在**：只剩一条轨道，没有别的轨道可借、也没有相邻轨道可取电，所以配置页直接把这两张卡隐藏（`src/renderer/app.js` 的 `syncSummary`），后端也忽略这两个选项。

## 8. 借道（稀疏音轨借道）

- 目的：只有十几个音的音轨不该独占一条主线。
- 判据：非主音轨、且音符数 < `sparseBelow`（默认 50）算稀疏（`src/core/arrangement/laneSharing.ts:95-101`）。
- 能否借：把 guest 的音符叠到 host 的同 tick 行之后，每个 tick 的个数仍要 ≤ 单列容量 `chordCapacity(dMax)`（`src/core/arrangement/laneSharing.ts:73-82`、`97`）。
- 排队：音多的 guest 先挑（难放的先放），挑「布局顺序上离得最近」的 host，同距离取顺序靠前的（`src/core/arrangement/laneSharing.ts:117-142`）。
- 放不下的 leftovers：≥2 条且合计 ≥ 50 音时合成一条新的「收集轨」，否则各自保留独立轨道（`src/core/arrangement/laneSharing.ts:144-161`）。
- 界面结果状态：已应用 / 借道未采用（合并后听距更近）/ 借道未生效（实测听距没有变近）/ 合并后没有音符很少的轨道 / 没有可借的轨道 / 已关闭 / 失败（`src/renderer/app.js:1863-1869`）。

## 9. 取电（相邻轨道取电、消除长车头）

- 现象：首音很晚的轨道，要从 X=0 起把「时间」运到那个位置，铺几千格粉、几百个中继器——这就是你说的「前面放中继器很稀疏、后面连着放」。区块加载跟不上，这条轨道就断。
- 做法：如果附近某条轨道在同一列已经有「这个时刻」的红石粉，就从那里借一次电。走廊里每跨一行放一个中继器（朝向指输入侧），每行多 1 红石 tick（`src/core/layout/index.ts:441-493`；`src/core/layout/track.ts:244-261`）。
- 约束：
  - 借电点必须是红石粉（中继器不能从侧面读）。
  - 走廊每一格与本轨道起点格必须空闲；走廊格左右不能是中继器（侧面中继器会锁死走廊里的中继器）。
  - 时间上：`prevRt`（宿主该格时刻 + 走廊行数）必须早于本轨道首音，并且之后还留得下补齐链：`chain = ceil((atRt − prevRt)/4)`，要求 `cell.x + chain + 2 ≤ target`。
  - 收益门槛：目标位置 < 24 格就不借（`src/core/layout/index.ts:382`、`454`）。
  - 兜底有两个：若借电后出现 `SPATIAL_DRIFT`，整条轨道退回自己铺车头（`src/core/layout/index.ts:729-734`）；若走廊与本轨道自己的分支行撞格（同一格写两次），整条轨道重建（`:735-741`，判定在 `:405-413`）。
- 选择：可用列里取最靠右（最晚）的那一列，同列取走廊最短的（`src/core/layout/index.ts:486-489`）。

## 10. 注释牌（投影自己会说话）

- 每条轨道前（电路西侧 3 格）立一块朝 -X 的墙牌加一块底座：金块 = 主音轨 / 全曲主线，铜块 = 副轨 / 未指定主轨（`src/core/layout/annotation.ts:83-94`、`119-152`）。
- 牌面四行：角色（主音轨 / 副轨 / 音轨 / 全曲主线）+ 轨号（≤3 条源音轨写「轨 3+7」，否则「共 N 轨」）+ 力度（该轨道最强源音轨的平均力度百分比）+ 站位或距离（主轨「站这里」；副轨「距主轨 N」；全曲主线「站这里 / 主线行」）（`src/main/generate.ts:406-413`、`src/core/layout/annotation.ts:135-142`）。
- 玩家站位：主音轨的红石粉那一行（布局里固定 z = 0，`LayoutResult.playerZ`）；全曲一条主线时站 spine 那一行。第十一轮之前是“没有主音轨取 Z 中点”，那条路已经不存在——主音轨永远都有（`src/core/layout/hearing.ts`、`src/core/layout/annotation.ts:112-117`）。
- `spreadZ` 现在就是听距半径：`generate()` 把 `result.hearingRadius` 传给注释牌（`src/main/generate.ts` 的 `laneLegend`），界面显示「最远 N 格」；不传时注释牌退回按各轨道 zMin/zMax 估一个值（`src/core/layout/annotation.ts:154-169`）。
- 注释牌是独立 region，可以在 Litematica 里单独删掉或搬走（`src/core/layout/annotation.ts:14-16`）。

## 11. 命令播放后端

- 不铺红石：把整首歌压成一张「每个 tick、每种音色的每个音高各有多少个」的表，再用命令方块链 + `playsound` 在玩家自己位置播放（`src/core/command/index.ts:20-32`）。
- 好处：没有 48 格听距、没有复音上限；代价：需要能开命令方块，链长受 gamerule 限制。
- 结构：命令链折叠成 32×32 的蛇形层（`src/core/command/player.ts:14-34`）；预算默认 65536 条命令，超了直接报错（`src/core/command/index.ts:35`）；同一 tick 超过 31 个音会警告（原版音符盒复音边界，`src/core/command/index.ts:38`）；方块数超过 4096 会警告（粘贴成本，`src/core/command/index.ts:56`）。
- 场景：命令后端没有「轨道排布」，所以借道 / 居中 / 取电 / 注释都不适用，界面会禁用并解释（`src/renderer/app.js` 的 `syncSummary()`，从 `:612` 起）。

## 12. 界面上的读数是什么意思

- `X × Y × Z`：最终布局的外接尺寸。Z 是任何方块伸到的最远距离（轨道铺开的总宽度），它**不等于**听距：听距是「站行到最远音符」的半径，读数里单独写「最远 N 格」。
- `MC 轨道 N 条` vs `源音轨 N 条`：前者是生成出来的红石轨道数（合并 / 借道之后），后者是 MIDI 里参与生成的音轨数。
- `区域`：litematic 里 region 的个数。默认每条轨道一个，注释牌 +1；被借道走廊穿过的高和弦轨道会按 Z 行拆成几条带，所以这个数可能大于「轨道数 + 1」。
- `方块`：所有方块放置数（含支撑块与地板），不是「非空气方块」。
- `提示`：warning 条数，每种都有中文解释（`src/renderer/warningText.js`）。

## 13. 我们模拟了什么、没模拟什么

- **有**：按原版源码移植的红石模拟器（`src/core/sim/redstone.ts`）。红石粉每格 −1；中继器只读自己朝向的输入、延迟 d×2 游戏刻；侧面输入不供电；音符盒只在上升沿响一次；未加载区块阻断信号。用它跑过 7410 个音符全部准点。
- **没有**：区块加载的**时间顺序**（玩家走过去才加载）、方块更新顺序、服务器性能与 `maxCommandChainLength`、版本漂移（源码是 1.12.2 反编译，导出目标是 1.20.4）。
- 结论因此是：理想红石模型下「多轨不同音」不存在（7410/7410 准点）；能解释「歌中间断掉」的是区块加载。实测探针：玩家站起点（半径 11 区块）只响 4%，以 0.4 格/刻向东走只响 22%。
